| Field | Value |
| ----- | ----- |

| Date | 2026-11-26 |

## Verdict

**Not accepted as is.** The structure is good: every requirement has a user story and acceptance criteria in EARS format, and the §5 decisions are respected. The problems are elsewhere:

- **5 endpoint paths contradict the assignment.**
- **The frontend is under-specified.** There are 24 Web criteria against 90 API criteria, and most of the Web criteria are NFRs.
- **Several criteria the assignment requires are missing.**

These would propagate into `design.md` and the code, so they have to be fixed in the requirements phase.

## What Kiro got right (keep)

- Every requirement has a user story and at least one acceptance criterion, which satisfies the rubric.
- §5 decisions are carried over correctly:
  - `404` for non-members and `403` for missing role or ownership
  - the token cookie plus `AuthContext`
  - card soft-delete
  - `is_done` and `completed_at`
  - notification triggers N1–N3
  - the envelope, with delete returning `200 { data: { id } }`
  - the FLOAT strategy with rebalancing
- Nothing from §11 (out of scope) leaked in.
- The NFRs were turned into measurable criteria (500 ms p95, 375 px, 44 px tap targets).

## Root cause

Brief v0.1 never listed the assignment's exact routes or page behaviors, so Kiro filled the gaps with "REST-ish" nested paths of its own. The fix goes in two places:

1. **Brief v0.2** adds Appendix A (endpoint catalog) and Appendix B (frontend behaviors).
2. **Targeted refinement prompts**, one per finding category, listed below.

## Refinement prompts

Process for each round:

1. Paste the prompt into the same Kiro Spec session.
2. Open **View changes** and check that only the targeted items changed.
3. Commit with `docs(specs): refine requirements rN — <topic>`.
4. Write the `CHANGELOG.md` entry (before → after), using the git diff as evidence.

Stay in the requirements phase until all five rounds are done. Do not click "Generate Tech Design" yet.

### R1 — Endpoint paths

```text
Refinement round 1 — endpoint paths.
Re-read specs/project-brief.md with your file-read tool: it is now v0.2 and has
Appendix A, a canonical endpoint catalog. requirements.md violates it in 5 places:

3. Column reorder is merged into the column PATCH. Append a separate criterion to REQ-6

   that board) and order (float > 0).
4. REQ-10.4 and REQ-10.5 use /api/cards/<card_id>/comments/<comment_id>
   → must be PATCH /api/comments/<id> and DELETE /api/comments/<id>
5. REQ-11.6 uses PATCH /api/notifications/<id> → must be PATCH /api/notifications/<id>/read
Then compare every other path in the document against Appendix A and report any mismatch.
Change only these items; keep every other criterion word-for-word and keep existing
criterion numbers. At the end, list every edit you made.
```
