## Verdict

**Not accepted as is.** Every rubric item for `design.md` is met:

- `POST /api/auth/register` and `POST /api/auth/login` are listed.
- `Card.order = db.Column(db.Float)`.
- Every model has a UUID primary key, `created_at`, `updated_at`, and `deleted_at` on `Card`.
- All 30 endpoints from Appendix A are present.
- The 8 blueprints each have `routes.py`, `service.py` and `schema.py`.
- Werkzeug hashing is named (the follow-up from CL-06).

The review still found **7 defects that would break the running app or a graded E2E scenario**, plus gaps in the API contract and the data layer. These are much cheaper to fix in the design than in the code.

## What Kiro got right (keep)

- The endpoint catalog has auth level, request body, success shape and every error code, all consistent with the requirements.
- The authorization model (`404` for non-members, `403` for role or ownership) is stated once and applied consistently.
- The FLOAT strategy, the `completed_at` lifecycle, token dual-storage, soft delete and the notification triggers all match brief §5.
- The traceability table covers REQ-1 to REQ-32.
- `UserUpdateSchema` rejects `password`, and `RegisterSchema` enforces `min=8`.

## Findings

Severity:

- **Blocker**: the app breaks, or a graded scenario fails.
- **Major**: wrong or inconsistent behavior.
- **Minor**: quality or consistency issue.

| # | Location | Problem | Severity | Round |
| - | -------- | ------- | -------- | ----- |
| D1 | Error Handling table | Marshmallow's `ValidationError` is mapped through `@app.errorhandler(422)`. Plain Marshmallow raises a Python exception, not an HTTP 422, so the handler never fires and **every validation error becomes `500`** through the catch-all handler. It must be `@app.errorhandler(ValidationError)` returning `400`. | Blocker | DR1 |
| D2 | Error Handling table | A catch-all `@app.errorhandler(Exception)` also catches Werkzeug `HTTPException`s that have no specific handler, such as a malformed JSON body (`400`) or `415`. Those would also become `500`. An `HTTPException` handler is needed that keeps the original code inside the envelope. | Blocker | DR1 |
| D3 | Error Handling table | "JWT error handlers → 401" does not say how. Flask-JWT-Extended's defaults return `{"msg": ...}`, which breaks the envelope, and a malformed token returns **`422`**, not `401`. `unauthorized_loader`, `invalid_token_loader` and `expired_token_loader` must be overridden to return `401 { "error": ... }`. | Blocker | DR1 |
| D4 | `Notification` model | `card_id` and `board_id` are foreign keys with no `ondelete`. Hard-deleting a board, or a column with its cards, that a notification references raises an IntegrityError, so **`DELETE /api/boards/<id>` returns `500`** once any `board_invite` exists. They need `ondelete="SET NULL"`. | Blocker | DR1 |
| D5 | Frontend structure | `middleware.ts` is placed inside `app/`. Next.js only runs middleware from the project root (or `src/`); inside `app/` it is silently ignored, so **no route protection** and Playwright auth scenarios 3 and 4 fail. (Next.js 16 renames the file to `proxy.ts`; use whichever the installed version expects.) | Blocker | DR1 |
| D6 | `app/layout.tsx` | The root layout renders `Header` on every page, including `/login` and `/register`. `NotificationBell` would poll `GET /api/notifications` without a token, get `401`, and `useErrorHandler` would toast "session expired" and redirect, which **loops on the login page**. Header and providers that need auth belong in an authenticated route-group layout. | Blocker | DR1 |
| D7 | Backend and frontend structure | Both trees start at `app/`: Flask's `app/` package and Next.js's `app/` router. They cannot share one repository root. The repo needs `backend/` and `frontend/` roots, as planned in the README. | Blocker | DR1 |
| D8 | `Column.cards` + `joinedload` (REQ-19) | Eager-loading `Board.columns → Column.cards` through the plain relationship **includes soft-deleted cards**, which violates REQ-5.3. The loader needs `selectinload(Column.cards.and_(Card.deleted_at.is_(None)))` or a filtered relationship. | Major | DR1 |
| D9 | Endpoint catalog | Response bodies say "card fields…", "comment fields…", "notification fields…". Only input schemas are defined. `/my-tasks` must group by board **name** (REQ-12.4), but the card response has no `board_name`, and `CommentList` needs the author's **name**, but the comment response only has `author_id`. Output (dump) schemas are needed. | Major | DR2 |
| D10 | FLOAT strategy + position endpoint | The client sends `order`. If the server then **rebalances**, the client's other cards keep stale `order` values, and the next drag in the same session computes from wrong neighbors and lands in the wrong slot. The position response must say whether a rebalance happened and return the column's new orders, or the client must refetch. | Major | DR2 |
| D11 | `ColumnReorderSchema`, `CardPositionSchema` | `Range(min=1e-10)` does not mean "> 0": it rejects valid values between 0 and 1e-10. It should be `Range(min=0, min_inclusive=False)`. | Minor | DR2 |
| D12 | `CardQuerySchema` | `assignee = fields.String()` accepts any value, but only `me` is defined. It should be `OneOf(["me"])`. Behavior with no query parameters is also undefined. | Minor | DR2 |
| D13 | Notifications error row | The text still says "`page` < 1", which is out of date after R4 (non-integer page also returns `400`). | Minor | DR2 |
| D14 | All models | `datetime.utcnow` is deprecated since Python 3.12 and produces naive datetimes. The frontend would read them as local time. Use `db.DateTime(timezone=True)` with `default=lambda: datetime.now(timezone.utc)`. | Major | DR3 |
| D15 | All models | No indexes on foreign keys, and PostgreSQL does not index them automatically. NFR-2 (500 ms p95) and `GET /api/cards?assignee=me` need `index=True` on `columns.board_id`, `cards.column_id`, `cards.assignee_id`, `comments.card_id`, `notifications.user_id` and `board_members.user_id`. | Major | DR3 |
| D16 | `Column` model | A model class named `Column` collides with SQLAlchemy's `Column` name and invites import shadowing. Rename the class to `BoardColumn` and keep the table name `columns`. | Minor | DR3 |
| D17 | `config.py` | Railway's `DATABASE_URL` uses `postgres://`, which SQLAlchemy rejects (brief §12). The design has no normalization step. The frontend `.env.example` (`NEXT_PUBLIC_API_BASE_URL`, `API_BASE_URL`) is also missing, even though it is a graded deliverable. | Major | DR3 |
| D18 | Traceability table | It maps per **REQ**, not per acceptance criterion. The rubric says "every acceptance criterion maps to a Flask route or Next.js page". Mixed rows such as REQ-10 (API and UI) need criterion ranges (for example "10.1–10.8 → comments blueprint; 28.4–28.9 → `CommentList.tsx`"). | Major | DR4 |
| D19 | Frontend structure | `BaseModal` must wrap the create-board, add-column and add-card forms (REQ-32.5), but none of those form components exist in the structure. The Dashboard is a Server Component, so its create-board form needs a client component and a `router.refresh()` afterwards. | Major | DR4 |
| D20 | Testing Strategy | **Hypothesis** (property-based testing) is introduced. It is not in the brief's tech stack and the prompt said "do not invent". Remove it, and test Properties 1–3 with ordinary pytest cases. | Minor | DR4 |
| D21 | Testing Strategy | "`useErrorHandler` is tested … to verify rollback". Rollback belongs to `useDragAndDrop`, not `useErrorHandler`. | Minor | DR4 |
| D22 | Property 6 | Still references "Requirements 18.1", which became "Covered by REQ-2.4" in R5. | Minor | DR4 |
| D23 | Error Handling text | "routes.py catches [service exceptions]" means try/except in every route. Raising one `AppError(status, message)` and handling it once in the app factory keeps `routes.py` thin (REQ-22.1). | Minor | DR4 |

### DR1 — Blockers

```text
Design refinement round 1 — blockers. Fix exactly these in design.md:
1. Error handling: replace "@app.errorhandler(422)" with a handler for
   marshmallow.ValidationError that returns 400 { "error": "<first message>" }.
   Plain Marshmallow raises an exception, not HTTP 422.
2. Error handling: add a handler for werkzeug.exceptions.HTTPException that returns
   e.code with { "error": e.description }, so malformed JSON (400) and 415 are not turned
   into 500 by the catch-all Exception handler.
3. Error handling: specify Flask-JWT-Extended loaders — unauthorized_loader,
   invalid_token_loader and expired_token_loader — all returning 401 { "error": "..." }.
   (The library default is { "msg": ... } and 422 for malformed tokens.)
4. Notification model: card_id and board_id get ondelete="SET NULL", so deleting a board
   or a column does not fail with an IntegrityError.
5. Frontend structure: middleware.ts must be at the Next.js project root, not inside app/.
   Note that Next.js 16+ names this file proxy.ts.
6. Frontend structure: the root layout only holds AuthContextProvider and Toaster. Header
   (with NotificationBell) moves to an authenticated route-group layout, app/(app)/layout.tsx,
   that wraps /, /boards/[id], /my-tasks and /profile — never /login or /register.
7. Repository structure: the Flask project lives under backend/ and the Next.js project under
   frontend/. Update both folder trees and every path in the traceability table.
8. GET /api/boards/<id> eager loading: specify
   selectinload(Board.columns).selectinload(Column.cards.and_(Card.deleted_at.is_(None)))
   so soft-deleted cards are not loaded through the relationship.
Change nothing else. If you notice any other problem, report it at the end instead of
fixing it. List every edit at the end.
```

### DR2 — API contract

```text
Design refinement round 2 — API contract. Fix exactly these:
1. Add a "Response Schemas" section with Marshmallow dump schemas, and use them in the
   endpoint catalog instead of "card fields...":
   - UserOut: id, name, email (never password_hash)
   - BoardOut: id, name, role (the current user's role), created_at
   - ColumnOut: id, board_id, name, order, is_done
   - CardOut: id, column_id, board_id, board_name, title, description, priority, due_date,
     order, completed_at, created_by, assignee { id, name } | null
   - CommentOut: id, card_id, content, created_at, updated_at, author { id, name }
   - NotificationOut: id, type, message, is_read, card_id, board_id, created_at
   - MemberOut: user_id, name, email, role
   board_name is needed by /my-tasks (REQ-12.4); author.name is needed by CommentList.
2. PATCH /api/cards/<id>/position success body: { "data": { "card": CardOut,
   "rebalanced": bool, "column_orders": [ { "id", "order" } ] } }. column_orders is
   only filled when rebalanced is true. useDragAndDrop applies column_orders to local state
   so the next drag uses fresh order values. Apply the same pattern to the column reorder
   endpoint.
3. ColumnReorderSchema and CardPositionSchema: order uses
   validate.Range(min=0, min_inclusive=False) instead of Range(min=1e-10).
4. CardQuerySchema: assignee = fields.String(validate=OneOf(["me"])). GET /api/cards with
   neither assignee nor board_id returns 400 { "error": "assignee or board_id is required" }.
5. GET /api/notifications errors: "page is not an integer >= 1, or per_page is not an
   integer from 1 to 100" (matches REQ-11.9).
Change nothing else. If you notice any other problem, report it at the end instead of
fixing it. List every edit at the end.
```
